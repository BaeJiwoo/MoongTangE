# 계속 플레이하는 성장·생존 — Issue #93

입장 즉시 시작하여 먹고, 성장하고, 다른 플레이어를 피하거나 먹으며 계속 플레이합니다.
제한 시간, 목표 수집량, 승리 조건, 결과 화면, 방 전체의 다음 판이 없습니다.
싱글플레이와 TCP 멀티플레이는 같은 `GameRoom::m_world`를 사용합니다.

## 참고한 Agar.io 규칙과 적용 범위

[Miniclip 공식 안내](https://support.miniclip.com/hc/en-us/articles/4404685562641-How-to-start-playing-Agar-io)
(확인: 2026-11-17)는 먹이와 작은 상대를 먹어 질량을 키우고 큰 상대를 피하는 기본 규칙을
설명합니다. 시간 제한은 별도 Rush 모드, 최후 생존자 승리는 Battle Royale 모드로 구분합니다.
이 프로젝트는 그 성장·생존 흐름을 참고하고 사용자의 요청대로 종료 없는 플레이를 제공합니다.

원작 안내에는 마우스 이동, 분열과 질량 발사도 있습니다. 현재 버전은 3D 캐릭터와 WASD를
사용하며 분열·질량 발사는 구현하지 않습니다. 지뢰는 사용자가 선택한 질량 40% 감소 효과입니다.
원작의 세부 수치나 서버 규칙을 그대로 복제한다고 주장하지 않습니다.

## 플레이와 화면

- 음식은 자신보다 크지 않을 때만 먹을 수 있으며, 먹으면 사라지고 캐릭터 자체가 커집니다. 주황색 테두리는 아직 먹을 수 없는 큰 음식입니다. 계속 새 음식이 보충됩니다.
- 상대보다 부피가 15% 이상 크면 접촉 시 상대를 먹습니다. 비슷한 크기는 서로 밀려납니다.
- 왼쪽 위에는 현재 질량과 지름, 오른쪽 위에는 **생존자들의 현재 질량 순위**를 표시합니다.
  순위는 실시간이며 1위가 되어도 게임이 끝나지 않습니다. 지뢰 피해나 재시작으로 순위도 바뀝니다.
- 기본 질량은 1.0, 기본 반지름은 0.5m입니다. 질량은 반지름 비율의 세제곱에 비례합니다.
  음식 누적 횟수나 예전 라운드 점수로 순위를 정하지 않습니다. 동률은 플레이어 ID 순입니다.
- WASD 이동, ESC 메뉴, F3 디버그입니다. 정지 중에도 입 애니메이션이 계속 재생됩니다.
- 탈락하면 Enter/R 또는 PLAY AGAIN으로 자신만 기본 크기로 재시작합니다. 다른 참가자의
  크기·위치, 음식과 지뢰, 월드 Tick은 초기화되지 않습니다. 살아 있을 때 Enter/R은 재시작하지 않습니다.

## 확장 맵과 장애물

96×96m 경기장에 바위 10개와 진흙 구역 6개가 고정 배치됩니다. 바위는 모든 크기의 캐릭터를 막고, 진흙에서는 목표 이동 속도가 평소의 45%가 됩니다. 지뢰는 기존의 질량 감소 효과를 유지합니다. 레이더는 바위(회색), 진흙(갈색), 지뢰(초록), 먹을 수 있는 음식(금색), 큰 음식(주황)을 구분합니다.

## 방의 수명과 계속 진행하는 월드

- 준비 대기 없이 첫 Tick부터 입력을 처리합니다. 과거 90초·20개 수집 경계를 넘어도 계속 진행합니다.
- 참가자의 입장·퇴장과 개인 재시작은 방 전체를 재시작하지 않습니다.
- 비어 있는 방은 Tick을 잠시 멈추고 기존 정책에 따라 기본 30초 뒤 정리됩니다. 만료 전에
  재입장하면 같은 월드가 이어지고, 만료되어 새로 만든 방은 새 월드로 시작합니다.
- 음식은 초기 144개, 최대 192개이며 0.25초마다 보충합니다. 지뢰는 피격 후 5초 뒤 재활성화되고
  피격자는 2초 보호됩니다. [세부 성장 규칙](COLLECTIBLE_SYSTEM.md)을 참고하세요.
- 성장 상한과 개수 제한은 서버 자원·수치 한도이며 승리나 종료 조건이 아닙니다.

## 구현과 호환성

`GameRound`와 라운드 점수 계산기를 제거하고 `GameRoom`이 `GameWorld`를 직접 소유합니다.
v12는 공유 정적 장애물 배치와 확장된 음식 한도를 버전으로 구분합니다. `FREE_PLAY`와 패킷 필드는 유지하지만 이전 클라이언트 접속은 거부합니다. 호환용 `round`는
ID/시간 0, FREE_PLAY, competitive=false이며 `round_score=0`, `round_winner=false`입니다.
과거 `next_round_id` 요청은 방을 초기화하지 않습니다. 이전 라운드 필드의 코덱 검증만
호환 목적으로 남으며 실행 중에는 라운드 상태를 만들지 않습니다.

`ContinuousPlayTests`는 300초 분량의 실제 입력·섭취, 과거 목표 초과, 오래된 다음 판 요청,
입퇴장과 빈 방 재입장 시 월드 보존을 검사합니다. `IntegrationTests`는 100초 분량의
직접/Protobuf 경로 일치와 실제 Local/TCP 탈락·재시작을 확인합니다. 화면 테스트는 질량 순위,
입 애니메이션, 탈락 후 재시작과 생존 중 Enter/R 무효를 검사합니다.
