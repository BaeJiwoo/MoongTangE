# 수집 물체 시스템

이 문서는 Issue #53의 결정론적 물체 소환, Issue #54의 공 부착, Issue #57의 변형 플레이어
콜라이더 규칙을 설명합니다. 게임 규칙과 물리는 `Common`, 월드 소유권은 서버 Tick 스레드,
GLB 로딩과 화면 표시는 `Client`에만 있습니다.

## 설계 근거와 적용 범위

Issue #57의 이중 프록시는 Namco와 원작 제작진이 출원한
[JP2005095324A](https://patents.google.com/patent/JP2005095324A/en)의 공개 실시 예를
참고합니다. 공개 자료는 화면 모델, 누적 부피로 커지는 충돌 판정 구체, 여러 방사형 팔 끝으로
굴림을 계산하는 모델을 분리합니다. 출시판 소스 코드가 공개된 것은 아니므로 동일 구현을
주장하지 않고, 서버 결정론과 현재 물체 크기에 맞춘 프로젝트 해석으로 사용합니다.

이 구현은 누적 부피 구체의 매끄러운 접촉을 유지하고 54개 방향을 사용하며, 물체 반지름까지
굴림 팔 길이에 반영합니다. 돌출은 인접 방향으로 퍼뜨리고 현재 누적 부피 반지름의 30%보다
작게 제한합니다. 특허 예시의 10% 획득 제한, 크기에 따른 최고 속도 조정과 충돌 시 부착물
분리는 현재 게임 규칙에 포함하지 않습니다.

## 소환 규칙

| 규칙 | 값 |
| --- | --- |
| 기본 월드 seed | `0x4d6f6f6e6754616e` |
| 시작 물체 수 | 8개 |
| 추가 소환 주기 | 300 Tick = 5초 |
| 최대 물체 수 | 24개 |
| 배치 영역 | X/Z 각각 `[-12, 12]` |
| 낙하 생성 높이 | Y=8 m |
| 기본 충돌 반지름·질량 | 0.35 m, 0.25 kg |
| 크기 범위 | 0.65–1.25배 |
| 물체 사이 추가 간격 | 충돌 반지름 합 + 0.75 m |
| 한 물체의 최대 배치 시도 | 256회 |

`GameWorld` 생성자는 참가자 입장 전에 시작 물체 8개를 공유 지형 위에 놓습니다. 시작 물체의
Y 좌표는 해당 XZ의 지형 높이에 크기가 반영된 충돌 반지름을 더하므로 첫 Tick부터 지표면 위에
안정적으로 놓입니다.
참가자가 있는 `GameRoom`만 `Step()`을 실행하며, 월드 Tick이 300의 배수에 도달하면 물체
하나를 Y=8에서 추가합니다. 추가 물체는 같은 `PhysicsWorld::Step()`을 통과해 중력과 지형
접촉을 적용받습니다. 24개에 도달하면 난수 상태도 소비하지 않고 소환을 건너뜁니다.

## 결정론과 seed 전달

난수는 표준 라이브러리의 분포 구현 대신 `DeterministicRandom`의 SplitMix64와 명시적인
53비트 정수→double 변환을 사용합니다. 같은 실행 순서와 seed는 물체 종류, 수평 위치, 초기
Y축 회전 및 크기를 같은 순서로 만듭니다. 배치 후보가 기존 물체와 너무 가까우면 해당 후보를
버리고 다음 난수를 사용합니다. 256개 후보가 모두 거부되면 그 소환 시도만 실패하며 ID와
물체 수는 증가하지 않습니다.

`GameRoomOptions::m_worldSeed`가 서버의 기준 seed입니다. 첫 번째 방은 기준 seed, 이후 방은
`기준 seed + roomId - 1`을 사용하므로 방마다 재현 가능하지만 서로 다른 배치를 가집니다.
방 ID와 부호 없는 64비트 덧셈은 자연스럽게 순환합니다.

- 싱글플레이: `Client --single --world-seed 42`
- 독립 서버: `DedicatedServer --world-seed 42`
- 원격 클라이언트는 서버 seed를 정할 수 없으며 `--connect`와 `--world-seed`의 동시 사용을
  거부합니다.

크기는 물체 ID와 seed에서 얻은 시작 offset으로 24개 슬롯을 순회합니다. stride 5와 슬롯 수
24는 서로소이므로 최대 개수에 도달하기 전까지 크기가 중복되지 않습니다. 반지름은 크기에
비례하고 질량은 크기의 세제곱에 비례합니다.

## 배치 판정과 물리

배치 간격은 높이를 제외한 XZ 거리로 검사합니다. 새 물체와 모든 기존 물체 사이 거리가
`새 반지름 + 기존 반지름 + 0.75` 이상이어야 합니다. 낙하 물체에도 같은 규칙을 적용하므로
이미 놓인 물체 바로 위에서 반복 생성되지 않습니다.

물체의 물리는 구형 `RigidBody` 근사입니다. 외부 물리 엔진을 사용하지 않으며 플레이어 공과
같은 중력, 공유 지형 접촉, 마찰, 구름 저항 및 자세 적분을 사용합니다.

## 물리 연산 요약

`p`, `v`, `q`, `ω`는 각각 위치, 선속도, 자세 quaternion, 각속도이고 `r`, `m`, `I`는
반지름, 질량, 관성 모멘트입니다. 고정 시간 간격 `Δt=1/60초`, 중력
`g=(0,-9.81,0)`을 사용합니다.

| 단계 | 핵심 계산 | 결과 |
| --- | --- | --- |
| 크기 반영 | `r=0.35×scale`, `m=0.25×scale³` | 화면 크기와 충돌 구·질량이 함께 변합니다. |
| 자유 낙하 | `v←v+gΔt`, `p.y←p.y+v.yΔt` | 새 물체가 Y=8에서 공유 지형으로 떨어집니다. |
| 지형 접촉 | 지형 법선으로 침투를 보정하고 안쪽 접촉 속도에 충격량 적용 | 구가 평면·뾰족 지형·언덕 안으로 침투하지 않습니다. |
| 지면 이동 | 접지 중에만 `v←v+FΔt/m` | 플레이어 입력력이 공중에서는 작용하지 않습니다. 물체의 `F`는 0입니다. |
| 구름·마찰 | `I=2mr²/5`, 접촉점 미끄럼에 제한된 충격량 적용 | 선속도와 각속도를 연결하고 서서히 정지시킵니다. |
| 자세 적분 | `q←normalize(fromRotation(ωΔt)×q)` | 공과 자유 물체가 실제 각속도에 따라 회전합니다. |
| 획득 판정 | 자유 물체 중심과 누적 부피 기반 획득 구체를 검사 | 돌출된 부착물 끝이 아니라 매끄럽게 커지는 공 표면에서 물체를 얻습니다. |
| 접촉면 고정 | 물체 중심을 현재 획득 구체 표면에 고정 | 일부가 공 안에 묻히고 나머지가 밖으로 돌출되는 괴혼식 배치가 됩니다. |
| 부착 추적 | 공 기준 `localPosition`, `localOrientation`을 매 Tick 월드로 변환 | 물체가 공의 자식처럼 평행 이동·회전합니다. |
| 부착 순간 | 플레이어 `RigidBody`에 충돌 충격량을 적용하지 않음 | 물체가 붙는 순간 공이 튀거나 감속하지 않습니다. |
| 굴림 프록시 | 성장하는 기본 구체와 완만하게 제한된 54개 방사형 팔 중 최저 지지점을 선택 | 물체가 많아지면 오래된 돌출을 흡수하면서도 최근 부착 방향은 구름 운동을 바꿉니다. |
| 소유자 퇴장 | `v_object=v_player+ω_player×offset`을 유지하고 소유 ID를 0으로 변경 | 마지막 표면 속도에서 자유 물리로 자연스럽게 전환합니다. |

자유 구의 바닥 마찰은 접촉점의 미끄럼 속도
`slip=(v.x,0,v.z)+ω×(0,-r,0)`에서 충격량을 구합니다. 변형 플레이어 콜라이더는 아래의 실제
접촉 팔 `a`를 대신 사용합니다. 지면 선형 감쇠와 구름 저항도 적용하며 충분히 느려진 물체는
정지 처리합니다. 공-물체 부착 순간에는 이 충격량 계산을 사용하지 않고 상태 전이만
수행합니다.

## 공 충돌과 부착

아직 붙지 않은 물체는 물리 단계를 마친 뒤 플레이어의 매끄러운 획득 구체와 겹침을
검사합니다. 기본 공 반지름을 `R`, 이미 붙은 물체의 충돌 반지름을 `r_i`라고 하면 획득
반지름은 구 부피의 공통 계수 `4π/3`을 소거한 다음 식입니다.

```text
R_pickup = cuberoot(R³ + Σr_i³)
```

자유 물체의 공 로컬 중심 `c`가 `|c|≤R_pickup`이면 획득합니다. 물체 자체의 반지름이나
돌출된 굴림 팔은 이 겹침 판정에 더하지 않습니다. 따라서 길게 튀어나온 물체 끝에 다음
물체가 연쇄적으로 붙지 않고 전체 획득 영역은 계속 둥글게 성장합니다.

획득하면 물체 중심을 현재 획득 구체 표면 `normalize(c)×R_pickup`에 고정합니다. 두 중심이
정확히 같으면 고정된 위쪽 방향을 사용합니다. 그 시점의 상대 변환을 다음처럼 공의 로컬
좌표로 저장합니다.

```text
localPosition    = conjugate(playerOrientation) × (objectPosition - playerPosition)
localOrientation = normalize(conjugate(playerOrientation) × objectOrientation)
```

붙은 뒤에는 물체의 중력·바닥·충돌 물리를 더 이상 적분하지 않습니다. 매 Tick 플레이어 물리를
먼저 처리하고 아래 식으로 월드 변환을 다시 만듭니다.

```text
objectPosition    = playerPosition + playerOrientation × localPosition
objectOrientation = normalize(playerOrientation × localOrientation)
```

따라서 물체가 공 중심을 향해 계속 가속하거나 부착 순간에 공에 반작용 충격을 주지 않습니다.
물체 중심은 획득 구체 표면에서 멈추며 이후에는 공과 함께 평행 이동·회전합니다. 물체
반지름은 다음 Tick부터 누적 부피와 방사형 굴림 프록시에 반영되지만 별도의 강체나 복합 구
콜라이더로 남지 않습니다. 내부 물체 속도는 공 표면의 순간 속도
`linearVelocity + angularVelocity × worldOffset`으로만 갱신합니다. 플레이어가 퇴장하면 마지막
월드 변환과 이 속도를 유지한 채 소유 ID를 0으로 되돌리고, 다음 Tick부터 자유 물리 물체가
됩니다.

## 변형 플레이어 콜라이더

`DeformableBallCollider`는 획득 구체와 굴림 프록시를 분리합니다. 굴림 프록시는 X/Y/Z
양·음축 6개와 Fibonacci 구면 분포 48개를 합친 고정된 54개 단위 방향 `u_j`를 가집니다.
굴림의 기본 반지름 `R`은 고정된 코어 반지름이 아니라 획득 구체와 같은 누적 부피
반지름입니다.

부착 물체의 로컬 중심과 반지름을 `(c_i,r_i)`, 중심 방향을 `v_i=normalize(c_i)`, 물체의
바깥 반지름을 `E_i=|c_i|+r_i`라고 합니다. `v_i`와 가장 잘 정렬된 팔을 찾고 그 주변 30도
안쪽 팔에 smoothstep 가중치 `w_ij`를 적용합니다. 가장 가까운 팔의 가중치는 1이고 경계에서
0입니다. 기본 코어 반지름 `R_0`부터 물체 바깥 반지름까지의 변화만 분산해 원시 길이를
누적합니다.

```text
b_i       = max_j dot(u_j,v_i)
x_ij      = clamp((dot(u_j,v_i)-cos(30°)) / (b_i-cos(30°)), 0, 1)
w_ij      = x_ij²(3-2x_ij)
raw_j     = max(raw_j, R_0 + (E_i-R_0)w_ij)
```

실제 굴림 길이는 현재 누적 부피 반지름보다 밖에 남은 부분만 사용합니다. 돌출 상한
`C=0.3R`에 유리함수 soft-cap을 적용하므로 돌출량은 항상 현재 반지름의 30%보다 작고 값이
경계에서 갑자기 잘리지 않습니다.

```text
excess_j = max(0, raw_j-R)
bump_j   = C×excess_j / (C+excess_j)
L_j      = R+bump_j
```

`PlayerCollider()`가 매 Tick 현재 부착물 전체에서 프록시를 다시 만듭니다. `R`이 커지면 예전
물체의 `raw_j`와 차이가 줄어 돌출이 낮아지고, `R≥raw_j`가 되면 그 물체는 굴림 형상에 완전히
흡수됩니다. 같은 방향의 물체는 가장 바깥 원시 길이만 남습니다. 물체 모양 전체를 정확히
감싸는 콜라이더가 아니라 불규칙한 굴림을 만드는 저해상도 물리 프록시이므로 렌더링 모델의
세부 표면과 지형 접점이 완전히 일치할 필요는 없습니다.

월드 방향 `d`에 대해 성장한 기본 구체 지지점과 모든 팔 끝을 비교합니다. `q`는 플레이어
자세입니다.

```text
a_base = normalize(d) × R
a_j    = q × (u_j × L_j)
a      = dot(a,d)가 가장 큰 후보
```

`a`는 공 중심부터 현재 지형 접촉점까지의 월드 접촉 팔입니다. 지형 표본의 바깥쪽 법선을
`n`이라고 할 때 `a`는 `-n` 방향의 지지점이며, 법선 방향 침투 깊이만큼 중심을 보정합니다.
돌출 팔이 지형 쪽으로 회전하면 공 중심이 올라가고, 팔이 접촉면을 지나가며 방향과 길이가
바뀌어 덜컹거리는 굴림을 만듭니다.

접촉점 속도 `u`, 현재 지형 법선 `n`, 미끄럼 단위 방향 `t`를 사용한 충격량은 다음과 같습니다.
`I=2m playerRadius²/5`는 기존 공의 스칼라 관성 모멘트입니다.

```text
u   = v + ω×a
J_n = max(0,-dot(u,n)) / (1/m + |a×n|²/I)
J_t = min(|slip| / (1/m + |a×t|²/I), friction×J_n)
```

두 충격량을 접촉 팔에 적용하므로 부착물이 비대칭 위치에서 바닥에 닿으면 정상력과 마찰이
추가 토크를 만들고, 같은 입력에서도 기본 구와 다른 높이·속도·각속도로 굴러갑니다. 현재는
부착 순간의 운동량 급변을 피하기 위해 플레이어 질량과 관성 모멘트는 유지하고 접촉 형상과
지렛팔만 바꿉니다. 렌더링 공 메시 자체는 변형하지 않으며 부착된 GLB 모델들이 복합 형상을
표시합니다.

## Snapshot과 클라이언트 표시

프로토콜 v8의 `CollectibleState`는 다음 표시 상태만 전송합니다.

- 월드 안에서 단조 증가하는 0이 아닌 물체 ID
- `APPLE`, `BANANA`, `BURGER`, `DONUT` 종류
- 서버 권위 위치와 단위 quaternion 자세
- 0.65–1.25 범위의 크기
- 부착되지 않았으면 0, 부착되었으면 같은 Snapshot에 존재하는 플레이어 ID

클라이언트가 사용하지 않는 물체 속도와 각속도는 전송하지 않아 최대 32명과 24개 물체가
기존 8,192바이트 프레임 한도 안에 들어갑니다. 코덱은 0이 아닌 부착 플레이어 ID가 같은
Snapshot의 플레이어를 가리키는지 송수신 양쪽에서 검사합니다. 자유 물체는 같은 ID의 위치와
자세를 보간합니다. 부착 물체는 목표 Snapshot에서 공 기준 상대 변환을 복원한 뒤 보간된 공에
다시 적용하므로 Snapshot 사이에서도 공의 자식 오브젝트처럼 정확히 따라갑니다. 클라이언트는
물리를 예측하지 않습니다.

클라이언트는 실행 파일 옆 `Assets/Models`에서 Kenney Food Kit 2.0의 GLB 네 개를 로드합니다.
각 모델 bounding box의 가장 긴 축을 서버 충돌 지름 `2 × 0.35 × scale`에 맞추고 bounding box
중심이 서버 위치에 오도록 보정합니다. 이 처리는 화면 표현만 바꾸며 Common과 ServerCore에
raylib 의존성을 추가하지 않습니다. 에셋 출처, 원본 CC0 고지와 SHA-256은
[`Assets/README.md`](../Assets/README.md)에 기록합니다.

## Tick 소유권과 처리 순서

`GameWorld`와 내부 난수 상태, 물체 벡터는 해당 방을 담당하는 서버 Tick 스레드만 변경합니다.
네트워크 스레드는 완성된 `WorldSnapshot` 복사본만 직렬화합니다. 한 Tick의 순서는 다음과
같습니다.

1. 각 플레이어의 부착물로 누적 부피 획득 구체와 54방향 굴림 프록시를 만들고 입력·물리를
   처리합니다.
2. 붙은 물체는 소유 공의 로컬 변환으로 갱신합니다.
3. 자유 물체는 중력·바닥 물리를 처리한 뒤 중심이 플레이어 획득 구체에 들어오면 그 구체
   표면에 붙입니다.
4. 월드 Tick을 1 증가시킵니다.
5. 증가한 Tick이 300의 배수이면 최대 개수와 간격을 검사해 낙하 물체를 생성합니다.
6. 서버의 3 Tick 게시 주기에 맞춰 플레이어와 물체 상태를 Snapshot으로 복사합니다.

## 검증 기준

- 같은 seed의 두 월드는 시작 상태와 5초 후 낙하 상태가 같습니다.
- 다른 seed는 다른 위치를 만듭니다.
- 시작 물체의 ID·종류·크기 범위·고유 크기·최소 간격을 검사합니다.
- 5초 전에는 추가되지 않고 300번째 Tick 직후 Y=8에 하나가 추가됩니다.
- 24개 이후 다음 주기가 지나도 개수가 증가하지 않습니다.
- Protobuf round trip이 종류·위치·자세·크기를 보존하고 중복 ID, 알 수 없는 종류, 누락 필드,
  비정상 수치, 범위 밖 크기와 25번째 물체를 거부합니다.
- 최대 플레이어·물체 Snapshot이 프레임 상한 안에 들어가는지 검사합니다.
- 로컬 계산과 직렬화 경로의 물체 상태를 매 Tick 비교합니다.
- 획득 구체의 경계를 포함하고 경계 밖은 거부하며, 부착물 돌출 끝은 획득 영역에 포함하지
  않는지 검사합니다.
- 충돌한 물체의 공 기준 위치·회전이 이동과 회전 뒤에도 일정한지 검사합니다.
- 부착 순간까지 플레이어 운동이 독립 기본 구 계산과 같고, 이후 변형 콜라이더가 중심 높이와
  각속도를 바꾸는지 검사합니다.
- 누적 부피 반지름, 획득 표면 위치, 30% soft-cap된 방사형 팔 길이와 비대칭 접촉 팔이 만드는
  정상 충격 토크를 검사합니다. 반대편 물체가 누적되어 기본 반지름이 커지면 기존 돌출이
  기본 구체에 흡수되는지도 검사합니다.
- 존재하지 않는 플레이어를 가리키는 부착 상태를 인코딩·디코딩 양쪽에서 거부합니다.
- 플레이어 퇴장 시 물체가 같은 월드 위치에서 자유 상태로 바뀌는지 검사합니다.
