# 음식 섭취와 캐릭터 성장 — Issue #91

음식은 캐릭터에 붙지 않습니다. 서버 Tick이 접촉을 판정하면 음식 레코드를 제거하고 캐릭터의
부피를 증가시킵니다. 기존 복합 부착 방식은 Git 이력에 보존되어 있습니다.

## 성장과 조작

- 기본 반지름은 0.5m, 상한은 3m입니다. 음식의 대표 반지름은 `0.35 × scale`입니다.
- 같은 밀도의 구 부피로 `새 반지름³ = 기존 반지름³ + 음식 반지름³`를 계산합니다.
- 기본 이동 속도는 6m/s이며 `6 / (반지름 / 0.5)^0.25`로 커질수록 조금 느려집니다.
- WASD 방향을 정규화하고 목표 속도를 빠르게 추종합니다. 중립 입력에서는 빠르게 멈춥니다.
  입력이 120 Tick 동안 갱신되지 않아도 중립으로 전환합니다. 구르는 회전은 적용하지 않습니다.
- 96×96m 평면 경기장 안에 몸체 전체가 머물도록 제한합니다. 몸체 중심 높이는 반지름입니다.
- 다른 플레이어보다 부피가 15% 이상 크면 접촉 시 상대를 먹고 그 부피를 얻습니다.
  비슷한 크기는 밀려나며, 동시 접촉은 변경 전 크기로 판정합니다. 같은 희생자는 한 번만
  소비되고, 그 Tick에 자신도 먹힌 플레이어는 부피를 얻지 않습니다.

## 음식 배치와 섭취 기록

초기 144개, 최대 192개이며 플레이 중 15 Tick(0.25초)마다 빈자리에 하나를 만듭니다.
사과·바나나·버거·도넛의 scale은 0.4–2.0이며 생성 영역은 X/Z [-42,42]입니다.
고정 난수 변환과 seed로 배치를 재현합니다. 시작 통로, 바위, 다른 음식, 지뢰와 생존 플레이어를
피하는 후보를 최대 256번 검사합니다. 음식은 지면에 고정되며 낙하하거나 부착되지 않습니다.

Tick 전후 위치를 잇는 상대 이동 구간에서 원 충돌을 검사해 빠른 이동에서도 소비를 놓치지
않습니다. 동시에 닿으면 크기 조건을 만족한 플레이어 중 먼저 닿은 쪽이 먹고, 동률은 ID 순으로 결정합니다.
`foodEaten`은 사망·개인 재시작에도 유지되는 세션의 누적 섭취 기록이고 최대 4096회로
제한됩니다. 순위·승패에 사용하지 않습니다. 크기 상한에서도 음식은 소비되며 플레이가 계속됩니다.
소비한 ID는 다시 사용하지 않고, 현재 월드에는 먹지 않은 음식만 남습니다.

## 지뢰

고정 배치의 초록색 가시 지뢰 6개가 있습니다. 반지름 0.9m 미만 캐릭터는 안전합니다.
0.9m 이상이면 접촉 시 전체 부피/질량의 40%를 잃고, 남은 부피를 구의 반지름으로 환산합니다.
기본 크기 아래로 내려가지 않습니다. 따라서 지름이 바로 40% 줄어드는 효과는 아닙니다.

피격 플레이어는 120 Tick(2초) 보호되고 지뢰는 300 Tick(5초) 뒤 재활성화됩니다.
현재 질량 순위도 감소한 크기를 반영합니다. 서버의 `mineHitTick`과 지뢰의 `readyTick`으로 HUD와 색상을 표시합니다.

## 화면과 전송

`ChomperGeometry.h`는 입 벌림 각도와 구 표면 좌표를 계산합니다. `SceneRenderer::DrawBall()`은
입 부분이 열린 구, 두 입 안쪽 면과 눈을 그립니다. 초당 2.4회의 애니메이션은 정지 중에도
계속되고 이동 방향에 맞춰 몸체가 돌아섭니다. 캐릭터 크기에 따라 카메라 거리도 증가합니다.
`SnapshotInterpolator`는 위치·방향·반지름만 표시용으로 보간하며, 소비된 음식은 즉시 사라집니다.

프로토콜 v12은 플레이어 반지름·섭취 횟수·지뢰 피격 Tick과 최대 6개의 지뢰 상태를 전달합니다.
이전 `attached_player_id` 필드는 항상 0이어야 합니다. 클라이언트는 섭취·성장·피해를 예측하지
않으며 Local/TCP 모두 같은 GameWorld를 사용합니다.

음식은 기존 Kenney Food Kit 2.0의 CC0 GLB 에셋을 사용합니다. 모델의 가장 긴 축을 음식의
대표 충돌 지름에 맞추고 중심을 보정합니다. 새 외부 에셋이나 물리 엔진은 추가하지 않았습니다.
라이선스와 원본은 [THIRD_PARTY.md](../THIRD_PARTY.md)를 참고하세요.

## 크기 제한과 확장 지형 — Issue #95

음식 반지름은 `COLLECTIBLE_BASE_RADIUS * scale`입니다. 서버는 음식이 플레이어보다 크면 접촉해도 먹지 않으며, 성장한 뒤 다시 접촉하면 먹을 수 있습니다. 플레이어끼리는 더 큰 쪽만 기존 15% 부피 우위 조건으로 먹을 수 있습니다.

공유 `ArenaLayout.h`에 바위 10개와 진흙 6개를 정의합니다. 바위는 이동·성장·플레이어 간 분리 뒤에도 침투를 보정하며, 진흙 내부에서는 목표 이동 속도에 0.45를 곱합니다. 음식은 바위에서 떨어져 생성되고 개인 재시작은 바위·진흙을 피합니다. 레이더와 3D 화면 모두 같은 정적 배치를 사용하며 v12 핸드셰이크로 이전 배치의 클라이언트를 거부합니다.
